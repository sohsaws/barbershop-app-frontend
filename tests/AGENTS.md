# Правила тестов фронтенда

- На текущем этапе пиши только unit-тесты функций на TypeScript (`.test.ts`) с Vitest. React-компоненты пока не тестируй.
- Проверяй результаты функций, ошибки и граничные случаи. Состояние Zustand изолируй между тестами.
- При проверке функций подменяй внешние зависимости средствами Vitest; не выполняй реальные запросы.
- Не подключай unit/component-тесты к работающему Java API, туннелям, S3 или существующим базам. Не используй реальные токены и `.env.local` как тестовые фикстуры.
- Тесты реальных интеграций требуют отдельного согласованного стенда с одноразовыми ресурсами и отдельной команды. Не добавляй их в обычный `npm test`.
- Учитывай отсутствие layout-движка в jsdom: размеры, overflow и анимации проверяются отдельно в браузере, а не фиктивными DOM-измерениями.
- Не скрывай ошибки с помощью `.skip`, `.only`, больших snapshot-файлов или увеличения timeout без выяснения причины.
- Перед завершением выполняй `npm run test:check`; при изменении конфигурации также `npm run test:coverage` и `npm run build`.
