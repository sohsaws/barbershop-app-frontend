# Тесты фронтенда

На текущем этапе используются unit-тесты на TypeScript с Vitest 5. Инструменты RTL установлены для будущих компонентных тестов. Рекомендуется Node 24 LTS версии 24.15 или новее; допустимые версии указаны в `package.json`.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm test` | Один запуск всех unit-тестов |
| `npm run test:watch` | Перезапуск затронутых тестов при правках |
| `npm run test:check` | ESLint тестов, TypeScript тестов, все тесты |
| `npm run test:coverage` | V8 coverage, HTML в `coverage/index.html` |
| `npm run test:service-edit` | Сохранение услуги и подготовка галереи |
| `npm run test:feedback` | Форматирование ошибок и политика фото |
| `npm test -- tests/service-edit.test.ts` | Один файл |

В VS Code рекомендовано официальное расширение `vitest.explorer`. CI использует Node 24, проверяет типы и lint, запускает тесты с coverage и сохраняет отчёт как артефакт. Процент покрытия показывается для всего `src`; стартовые тесты не означают полное покрытие приложения. Порог покрытия пока не установлен.

## Окружение и изоляция

`vitest.config.ts` переиспользует Vite aliases и запускает тесты в Node.

`tests/setup.ts` возвращает реальные таймеры. Vitest очищает/восстанавливает моки и отменяет `vi.stubGlobal` / `vi.stubEnv` между тестами.

Внешние зависимости функций подменяются средствами Vitest. Реальные интеграции оформляются отдельной командой и используют согласованные одноразовые ресурсы.

## AI-хуки Codex

`.codex/hooks.json` регистрирует два события:

- `PostToolUse` после `apply_patch` / `Edit` / `Write`: если изменены `src`, `tests`, конфигурация тестов или пакеты, запускается `npm run test:check`.
- `Stop`: проверяет текущее содержимое перед завершением, в том числе после правок через shell. Успешный результат кэшируется по содержимому исходников, тестов, конфигурации и версии Node в системной temp-папке. При неизменившихся файлах повторный запуск пропускается.

Скрипт `.codex/hooks/test-check.mjs` возвращает Codex JSON с ошибкой, если проверка не прошла. Повторное продолжение с тем же неуспешным содержимым не создаёт бесконечный цикл: агент должен исправить ошибку или явно сообщить о блокировке. Хук не пишет в исходники, не выполняет commit/push и не вызывает внешние API.

Эти хуки запускают проверки, но не блокируют сетевые запросы агента или тестов. Ограничения агента определяются его разрешениями и правилами проекта.

**Активация:** начните новую сессию Codex в этом доверенном репозитории и откройте `/hooks`, чтобы просмотреть и доверить определения. Codex требует доверие для новых/изменённых пользовательских хуков; оно не выставляется автоматически. В текущей сессии скрипт проверяется вручную. Git-хуки не устанавливаются.

Официальная схема событий и правила доверия: [Codex hooks](https://learn.chatgpt.com/docs/hooks).

## Скиллы и рекомендации

Установлены в `.agents/skills/` без изменения других скиллов; лицензии сохранены рядом с ними:

| Скилл | Источник и зафиксированная ревизия | Применение |
| --- | --- | --- |
| `vitest` | [antfu/skills](https://github.com/antfu/skills/tree/4a6bb39e7b45e26402eb215393c51ccf5df1ca4c/skills/vitest), `4a6bb39e7b45e26402eb215393c51ccf5df1ca4c` | Конфигурация, mocks, timers, coverage |
| `javascript-testing-patterns` | [wshobson/agents](https://github.com/wshobson/agents/tree/42203085cfc5736204bf0f6d436dff7e1da0bf3f/plugins/javascript-typescript/skills/javascript-testing-patterns), `42203085cfc5736204bf0f6d436dff7e1da0bf3f` | RTL, renderHook, фикстуры, изоляция и ошибки |

Эти скиллы — рекомендации. Правила безопасности проекта в `tests/AGENTS.md` имеют приоритет над общими примерами, включая примеры с удалением таблиц или подключением реальной БД.

Новые unit-тесты проверяют результаты функций, ошибки и граничные случаи. Предпочитайте маленькие детерминированные фикстуры; не устанавливайте Faker ради одной записи.

Примеры: `tests/service-edit.test.ts`, `tests/form-feedback.test.ts`, `tests/slot-dates.test.ts`. Условия запуска AI-хука проверяются отдельно. S3-тесты и работающий Java-бэкенд эти команды не запускают.
